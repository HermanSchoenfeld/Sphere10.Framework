# B-tree pure workload diagnostics

These are the 282 retained direct diagnostic cases: 3,000 records, 100 query/action selections, one independent reset warmup, and three actual reset batches. Intervals are approximate 95% Student-t intervals. The low sample count supports diagnosis and follow-up rather than a unique-optimum claim. The two rows for each workload use identical inputs and differ only in order.

Paging settings are the historical explicit 65,536-byte page / 16-MiB cache control, and file buffers are 4,096 bytes. FilePaged ordinary uses the then-nominated 256 candidate; it is distinct from the final shared ordinary 128 default. Current-Core paging confirmation is retained in the main recommendations report. Managed logical stream size is not a resident-memory measurement.

Work per timed batch: Read/Miss perform 100 selections; Scan enumerates all 3,000 entries once; Range performs 100 inclusive ranges of up to 16 keys; Group reads 100 groups of up to 8 entries. Insert creates all 3,000 entries. Update replaces 100 values. Recycle deletes and re-adds 100 entries. Those three mutations include the backend's Persist boundary. Reopen closes/reopens storage and reads 100 identities, with OS cache still warm. Rollback undoes 100 updates prepared outside timing and reconstructs the tree/header. Read/scan preparation verifies and warms the complete baseline outside timing.

FileStream flush, managed paged-buffer flush, mapped-view flush and transactional commit have different durability guarantees. Compare matched orders within a backend. OS-mapped reopen also truncates/reprovisions capacity. Every actual diagnostic batch has an oracle checksum and structural/cardinality verification outside timing.
