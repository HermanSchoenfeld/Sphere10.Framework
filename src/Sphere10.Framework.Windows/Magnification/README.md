# Magnification

Applies colour transformations to the desktop or to single displays through the Windows Magnification API.

`DisplayColorEffectRenderer` is the high-level entry point. `Render` takes one `DisplayColorEffect` per display and copies the request's matrices, so subsequent caller changes require another call. When every display shares one matrix it uses the full-screen colour effect, which the compositor applies without recurring application callbacks. When displays differ it shows each non-identity display through its own `MagnifierWindow`, refreshed by a `DisplayFrameClock` from the [Display](../Display/README.md) domain, so those displays trail the screen by about one frame. Capture membership and configuration are reconciled when a request is applied, while capture refresh and passive-overlay discovery continue on each frame.

`Rendering` chooses between the two paths from the next render request: `DisplayColorEffectRendering.Automatic` (the default) takes the cheapest path that can show the request, as described here; `PerDisplay` always renders through capture windows, even when every display shows the same matrix, so a product can show exactly the mode its user selected. A product that must stay on the full-screen effect gives every display one matrix and sets no exclusions or region source.

Full-screen changes can fade over `FadeDuration` (150 ms by default). Fades sample elapsed time into retained matrices, so a delayed frame skips obsolete samples and reaches the destination on the first available frame after the duration. Nonpositive durations and switches between rendering paths apply immediately. When a switch to capture windows starts beneath an active full-screen effect, the windows are created first with unchanged colours, which leaves the screen as it was, and take over the transformation in one step once they all exist; the screen then shows normal colours only until their first captured frame. `Clear` restores normal colours. `RenderingChanged` is an `EventHandlerEx` notification without arguments, and `Failed` is an `EventHandlerEx<Exception>` notification raised after restoring normal colours.

`SetExclusions(windows, executablePaths)` leaves selected window instances or apps unchanged on the next render request. It copies the rules. They need the capture path only while one of their windows is visible on the screen: until the first desktop reading finds one, and from three seconds after the last one has gone, displays that share a matrix stay with the full-screen effect, which has no frame of lag. Rules are watched on that path too, so a window that comes into view brings capture back. Visible window regions are clipped out of each magnifier host after subtracting higher windows, so an ordinary foreground window crossing an exception still receives its colour effect. Original windows remain in the captured source. The mechanism operates on whole window surfaces; it does not identify images inside them. Translucent windows are treated as composed surfaces, and DWM decorations without a native window region use their visible-frame bounds.

`SetRegionSource(source)` takes ownership of an optional `IDesktopRegionSource` that discovers smaller `WindowsWindowRegion` areas. Each result retains a verified top-level window identity and physical desktop rectangles. The renderer copies the rectangles and clips them through the same `WindowsDesktopRegionMask` used for whole-window exceptions; unselected foreground windows still receive the effect. Discovery itself belongs to the supplied source, not the renderer. Start, Stop, Dispose and source notifications use the renderer's UI thread; provider work must remain off that thread. Sources must cancel/invalidate old publications on Stop and join cleanup without waiting for UI dispatch.

A capture refresh holds the UI thread until the display's next frame, once for each display shown through a capture window, so three displays leave it free for only a few milliseconds in fifty. The renderer therefore calls the source's `Synchronize` before each window's refresh, which lets a source that moves its areas every frame have them applied about once a display frame instead of once after all the refreshes. `HideCaptureWindowsFromCapture` marks the capture windows as excluded from screen capture (`MagnifierWindow.IsHiddenFromCapture`), so a reader of the display's frames, such as a source that follows content on the screen, sees the content itself rather than the transformed copy. Screenshots, recordings and screen sharing then show the untransformed desktop while capture windows render; the full-screen effect is not affected.

An enabled source retains the compositor until visible regions first require capture. Capture windows then remain while regions are visible and for three seconds after the last one went, so temporary empty results while geometry refreshes do not switch the global compositor effect or recreate every display's host. Empty results remove the preserved areas immediately. After the hold the displays return to the full-screen effect without another render request; removing the source releases capture at once unless exceptions still need it, and a replacement source inherits capture through the hold. Empty source results still stop desktop mask queries. Clearing rendering stops discovery and removes its areas while retaining the configured source for the next active request. Source replacement and renderer disposal release it. Whole-window/application exceptions retain their existing lifetime and behavior independently of this source.

Window changes trigger coalesced worker queries through `Throttle`; an `ActionCache` keyed by verified process identity retains executable paths. Areas that only move within their windows are clipped to the last reading of the desktop and applied at once, and such a move confirms that reading no more than once a second. Unchanged geometry does not reapply native regions, and each capture window receives only the areas on its own display, so a change on one display does not reshape the others. Pausing rendering stops geometry subscriptions and joins outstanding reads. Configured live-window rules retain one destruction subscription so a recycled HWND cannot inherit an exception; this subscription performs no geometry or app queries while paused. Removing all rules releases it and retains the original compositor fast path. App paths also match future process instances; selected-window rules expire when that window closes.

When the last live window exception closes, its subscription is released. If no app rules or active source capture remain and the display matrices match, the renderer immediately returns to the compositor path after the native callback finishes. Verification also retires windows that disappeared before the subscription was installed, or whose handle/process identity changed; inaccessible or failed queries alone do not expire a rule. Retired window identities remain recorded, so reapplying unchanged configured rules cannot revive an expired exception. Different display matrices still use capture independently of exceptions.

`MagnificationSession` owns the process-level `MagInitialize`/`MagUninitialize` lifetime and the full-screen effect. `MagnifierWindow` is a click-through, topmost layered popup whose `WC_MAGNIFIER` child re-renders a desktop region at 1:1 scale through a colour matrix. It can exclude windows from the capture and restrict rendering to a source rectangle. Create, use and dispose all of these on one UI thread with a message loop, and keep the session alive longer than its windows. Only one application can own the full-screen effect, so `Render` throws a `Win32Exception` when another one holds it. Coordinates are physical desktop pixels. The native declarations are in `WinAPI.MAGNIFICATION` in the [WinAPI](../WinAPI/README.md) domain.
