# Windowing

Read-only queries over other processes' native windows, verified window messaging, isolated UI Automation capture and thread DPI awareness scopes.

All windows here are borrowed. `WindowsWindow` enumerates windows, reads the window under a point or the pointer, and reads bounds in caller or physical desktop pixels. It returns detached `WindowsWindowInfo` records that capture handle, class, process, thread and process start time. Later calls such as `GetPhysicalBounds` and `WindowMessageSender.Send` check that identity again before acting, so a reused handle is not mistaken for the original window. `WindowsWindowLayering` answers z-order questions without activating anything. `Tools.Windows.Windowing` exposes the same operations as instance methods through `Tools.Windows.Windowing`, adds `AllowForeground`, and is the preferred entry point.

`WindowsUiAutomationUtil.CaptureAsync`, reached through `Tools.Windows.UiAutomation`, reads a selected window's UI Automation Control View in a separate helper process so a hung provider cannot block the application. The helper is the application's own executable started with `WorkerArgument`, so the application's `Main` must call `WindowsUiAutomationUtil.TryRunWorker(args, out var exitCode)` first and return `exitCode` when it returns `true`. `WindowsUiAutomationOptions` sets node, depth and time budgets, and the capture returns detached `WindowsUiAutomationElement` rows. `ThreadDpiAwarenessScope` changes the current thread's DPI awareness and restores it on dispose on the same thread. Highlight and picker UI over these queries is in the Windows Forms project's `WindowHighlight` domain.

`Tools.Windows.Windowing.GetTopLevelTargetAsync` resolves a picked child to its verified top-level window and physical frame. `GetExecutablePathAsync` reads the verified window owner's executable. `GetApplicationExecutablePathAsync` reads the executable of the application the window shows, which differs for Store apps: Windows draws their top-level windows in one frame host (`ApplicationFrameHost.exe`) for all of them, with the app's own window inside, so the owner's executable would name every Store app at once. Application exceptions match a frame through either executable. Both execute complete native queries on workers. The magnification renderer's internal `WindowsWindowExclusionTracker` combines native change subscriptions with visible-region occlusion and process-identity caching; products configure rules through the renderer rather than subscribing or polling themselves.

`WindowsDesktopRegionMask` owns front-to-back region composition and native overlay-region application. Add every visible window in z order, preserving either its entire shape or selected physical rectangles, and obtain detached rectangles through `ToRectangles`. Ordinary foreground windows occlude preserved areas below them. `WindowsWindowRegion` pairs partial areas with their verified owner; `IDesktopRegionSource` provides detached updates on a consuming UI thread, independently of how those areas are discovered. The magnification renderer owns an assigned source and combines it with ordinary window/application exclusions. `GetVisibleAreas(window)` returns what the windows added so far leave uncovered of a window, and `IntersectAreas` clips areas to it. The renderer's exclusion tracker reads the desktop this way when a window event says it changed (tens of milliseconds with many windows open) and clips areas that only move within their windows to that reading at once, so a source may move areas every frame.

`Tools.Windows.UiAutomation.CreateMediaSession()` creates a lazy, asynchronous disposal owner for repeated media queries. It retains one isolated helper and bounded provider caches. `CaptureAsync` accepts a verified `WindowsWindowInfo` and returns detached image/video rectangles clipped to the physical window frame and known viewport ancestors. UI Automation supplies image semantics. Providers supporting MSAA/IAccessible2 also supply graphic roles and explicit `tag:video` metadata, including when their UIA legacy bridge is unavailable. Classification uses provider semantics without application, site, title or localized-name rules. Content without accessible media metadata and some in-page occlusion cannot be identified reliably.

Dispatch the helper protocols before ordinary application startup when using diagnostic capture, media capture or title-bar reads:

```csharp
if (WindowsUiAutomationUtil.TryRunMediaWorker(args, out var exitCode)
	|| WindowsUiAutomationUtil.TryRunTitleBarWorker(args, out exitCode)
	|| WindowsUiAutomationUtil.TryRunWorker(args, out exitCode))
	return exitCode;
```

For repeated queries, retain and then dispose the session:

```csharp
await using var session = Tools.Windows.UiAutomation.CreateMediaSession();
var capture = await session.CaptureAsync(verifiedWindow, cancellationToken);
```

`WindowsUiAutomationMediaCapture.IsPartial` means discovery may have omitted media. Each returned region still has current provider geometry. `CapturedAtUtc` records the start of the geometry refresh after discovery. A session walks a window's provider tree on its first read, when `CaptureAsync` is called with `rediscover`, and otherwise every `RediscoveryInterval` (five seconds by default); the reads in between only refresh known media. Defaults allow 750 ms each for discovery and geometry refresh, within a 1,750 ms helper request deadline. Cancellation and disposal join helper cleanup before completing. Provider failures return an unavailable capture.

`WindowsMediaRegionSource` implements continuous discovery on a supplied UI `SynchronizationContext`. Call `Start`, `Stop` and `Dispose` on that UI thread and consume its `Changed` and `Failed` events there. A discovery helper and at most four parallel refresh helpers isolate slow providers; desktop inventory completes independently. A newly discovered provider cache transfers to an unused refresh helper when possible. A window with media then stays with one refresh helper, because the provider elements a bounded traversal found live in that helper; a free helper never takes another helper's window. Incomplete rediscovery retains missing provider identities within the region limit and reads their current geometry again. It accepts geometry less than 750 ms old and expires published regions independently after two seconds. A moved, hidden or closed top-level window invalidates its regions immediately. Changes inside a window do not remove its regions; the read they trigger replaces them.

Reads follow the desktop's change events rather than a fixed tick. The source hooks object events (create, destroy, show, hide, reorder, location change, content scrolled, scroll-bar value change) and system events (foreground, scrolling start and end, minimize end), ignoring caret and pointer objects. An event from inside a tracked window brings that window's next read forward, no closer to its previous read than `WindowsUiAutomationMediaOptions.RefreshIntervalMilliseconds` (50 by default, 5 to 1000). A shorter gap follows scrolling more closely and asks more of the application. The first such read only refreshes the geometry of media the helper already knows, which takes a fraction of a tree walk; the tree is walked again once the changes have been quiet for 150 ms, or once a second while they continue. Helpers retain media that scrolled out of view, up to half the region limit, so it reappears with the next geometry read.

Discovery first asks the provider for every image and group in the window with one UI Automation descendant search, which the provider evaluates itself, so media is found at any depth for the cost of one request (60 to 200 ms on large browser pages, where a node-by-node walk needs about 2 ms a node and stops at its limits). Images qualify directly. A provider that bridges native accessibility objects exposes each group's HTML tag, and `video` settles it. Providers with their own UI Automation tree report a video element as a plain group with no tag, so each group in view of at least 64 pixels on both sides is checked once by its shape: a video holds nothing, or only player controls (buttons and at least one slider), and does not offer the Invoke pattern; a container holds content, and an empty group that can be invoked is a button. An empty, non-invokable group of that size that is not a video is therefore also preserved. The answer is remembered per element. Each kept element is clipped to its documents and scroll containers, found with a walker filtered to those, one request per container and shared between media under the same one. Requests are bounded by the query time budget through `IUIAutomation2`; a provider that fails or outruns the search is walked node by node from the next discovery on. Media that an application hides from assistive technology, such as an image inside an `aria-hidden` link or with an empty text alternative, is not in any accessibility tree and cannot be found.

In the node-by-node walk, content can overflow a container that is out of view itself, such as a page body one screen tall under a long feed, so a native-accessibility walk opens up to `MaximumOverflowedContainers` (16 by default) such containers after everything in view, largest first; hidden containers and out-of-view windows and documents are never opened. For the same reason a grouping whose box misses an in-view element does not clip it, while windows and documents always bound their content. A window the user brings forward or restores is read at once and ahead of the others, and one the source does not know yet triggers a new inventory. Windows that raise no events are read at fallback intervals: 500 ms for known media, five seconds for a window without media, and one second for the inventory. Subclasses call `RequestRefresh(handle, focused)` to report a change from another signal. Set `Windows` to the handles of the only windows to search; null, the default, searches every visible window, and an empty array searches none and takes no desktop inventory. A change to the selection is applied with an inventory requested at once, and a window that leaves it loses its published regions. Selecting only the windows that need it keeps every other application untouched and leaves the refresh helpers to those windows. Pass `WindowsUiAutomationMediaOptions` to the constructor to change the budgets or set `MinimumImageSize`, which leaves images narrower or shorter than that many physical pixels (icons, for example) out of the result; videos are kept at any size. `Stop` clears publications and cancels discovery, while `Dispose` joins the owned helpers and inventory. Assigning it to the magnification renderer transfers that lifecycle ownership to the renderer.

A tracking strategy places what the source publishes. `WindowsUiAutomationMediaOptions.TrackingStrategy` selects it by `WindowsMediaTrackingStrategy`, `WindowsMediaTrackerBase.Create` builds it, and a subclass of the source can supply another through `CreateTracker`. `ProviderReports`, the default (`ProviderReportMediaTracker`), shows media where its application last reported it. An application may update the positions it reports only about twice a second while its content scrolls, as Chromium does, so media then stays behind its content and jumps; reading more often returns the same positions. `ScreenMotion` (`ScreenMotionMediaTracker`) follows the content on the screen instead. Media that shares a scrolling area moves together: a worker reads a few narrow strips of every frame of that area through `DisplayFrameCapture`, through pictures and beside videos, measures the distance with `DisplayFrameMotion` and moves the area's media by it, raising `Moved`. What is published reaches the screen a frame or more later, so moving media is placed that much further along (content that is slowing is taken to go on slowing) and once more where it was measured when the movement stops. While an area moves, a report only adds and removes media, placed as far ahead of the report as the followed media is; after 700 ms without movement the report is taken as it is, which removes accumulated error. Nothing is read while no window has media. The frames must show the content itself, so a consumer that draws over it keeps its own windows out of them (the magnification renderer's `HideCaptureWindowsFromCapture`). On a page scrolling by itself at 300 to 490 pixels a second, areas stayed a median of 1 to 3 pixels from their pictures (90th percentile 5 to 7) and moved about 50 times a second while it scrolled, against 180-pixel jumps about twice a second with provider reports.

Each medium is a `WindowsWindowMedia` in `WindowsWindowRegion.Media`: its provider identity, kind, whole box (`Extent`) and `Clip`, the part of the window its containers leave it; `Visible` is their intersection. `WindowsUiAutomationMediaRegion` carries the same `Extent` and `Clip`, and `WindowsUiAutomationMediaCapture.Upcoming` lists media that is out of view with where it lies, so a tracker shows it the moment it scrolls in. `IDesktopRegionSource.Synchronize` raises `Changed` at once if the areas moved since it was last raised, for a consumer that holds the UI thread for a display frame at a time.

`WindowsTitleBarReader.Read` finds what occupies a physical strip of another window's title bar, as `WindowsTitleBarContent` rectangles. It walks the application's accessibility tree only through elements that reach into the strip, so a page beneath is never visited, and takes buttons, tabs, images, text and similar controls there as they are. When the application reports nothing there, it reads the window's own composed pixels with `PrintWindow`, unaffected by windows covering it, and `WindowsTitleBarSpace.FindContent` takes columns that differ from the plain background (or a smooth gradient) as content. A window that is not per-monitor aware is drawn at another scale than its physical size and its pixels are not read. `Source` says which reading was used, and `None` that neither could be. Both readings call into the other process, so `Tools.Windows.UiAutomation.CreateTitleBarSession()` runs them in an isolated helper within 0.8 s each; the executable dispatches it with `WindowsUiAutomationUtil.TryRunTitleBarWorker` beside the other helpers. `WindowsTitleBarSpace.FindFreeLeft` then steps left from a preferred place past whatever is in the way until a square of a given size keeps its gap from all of it. The Windows Forms project's [WindowTitleBar](../../Sphere10.Framework.Windows.Forms/WindowTitleBar/README.md) buttons place themselves this way.

Geometry consumers can call `Tools.Windows.Windowing.EnumerateAsync(includeProcessDetails: true, includeTitles: false, visibleOnly: true, cancellationToken: cancellationToken)`. Hidden and minimized windows are rejected before metadata queries, and omitted titles remain empty. Skipping captions avoids `GetWindowText` sending synchronous messages to the caller's own UI windows while an inventory worker is being joined. The existing enumeration overloads retain their original behavior.
